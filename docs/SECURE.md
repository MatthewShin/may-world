# SECURE

May World는 백엔드/인증/DB가 없는 정적 SPA다(자세한 구조는
[[ARCHITECTURE.md]]). 공격면이 작지만, 향후 agent가 기능을 추가하면서 실수로
그 전제를 깨지 않도록 지켜야 할 규칙을 정리한다.

## 현재 위협 모델

- 클라이언트 정적 자산만 배포 (Vite build 산출물). 서버 사이드 로직, 세션,
  DB 쿼리가 전혀 없으므로 SQLi/서버 RCE류는 해당 없음.
- 표시되는 데이터는 전부 저장소 내 하드코딩 더미 데이터
  (`src/data/golfCourses.ts`, `GalleryView.vue`의 `defaultContents`) —
  사용자 입력을 저장/재노출하는 흐름이 없다.
- 유일한 "입력"은 골프장 리스트의 필터 `<select>` 값이며, 서버로 전송되지
  않고 클라이언트 `computed` 필터링에만 쓰인다.

## 지켜야 할 원칙

1. **비밀키/토큰 하드코딩 금지.** 이 프로젝트는 현재 API 키가 필요 없다.
   외부 API(지도, 이미지 CDN 등)를 연동하게 되면 키를 소스에 커밋하지 말고
   `.env` + `.gitignore` 패턴을 쓰고, 클라이언트에 노출돼도 되는 키인지
   먼저 확인한다 (Vite는 `VITE_` 접두 env를 번들에 그대로 인라인한다 — 즉
   `import.meta.env.VITE_*`에 넣는 순간 사실상 공개된다).
2. **동적 HTML 삽입 금지.** `v-html`은 현재 코드베이스에서 쓰이지 않는다.
   새로 추가하지 말 것 — 특히 사용자 입력이나 외부 데이터가 섞일 여지가
   있는 텍스트는 항상 Vue의 기본 텍스트 바인딩(`{{ }}`)을 사용해 이스케이프
   되도록 한다.
3. **외부 데이터 소스를 붙일 때** (예: 더미 데이터 대신 실제 API로 전환):
   - fetch 대상 도메인을 명시적으로 화이트리스트로 관리한다.
   - 응답을 그대로 렌더링하기 전에 타입을 검증한다 (현재 `GolfCourse`
     인터페이스처럼 명시적 타입을 유지).
   - CORS/CSP 관련 설정이 필요해지면 `index.html`의 `<meta>` 또는 배포
     플랫폼 설정에 추가하고, 이 문서에 반영한다.
4. **개인정보.** `AboutView.vue`, `GalleryView.vue`에 실제 연락처
   (이메일/전화번호)가 하드코딩돼 있다 — 이는 사이트 소유자 본인이 공개
   의도로 넣은 정보이므로 유지해도 되지만, 더미 골프장 데이터나 새로 추가하는
   콘텐츠에 실존 인물/제3자의 개인정보를 넣지 않는다.
5. **의존성.** `npm audit`으로 알려진 취약점을 주기적으로 확인한다. 새 패키지를
   추가할 때는 유지보수 상태와 번들 크기 영향을 함께 고려한다 (이 프로젝트는
   의존성이 매우 적은 상태를 의도적으로 유지하고 있다).
6. **파괴적 변경 금지.** `docs/*.md`, 더미 데이터, 디자인 토큰을 대량으로
   덮어쓰는 작업은 사전 승인 없이 하지 않는다 (전역 규칙).

## 배포 시 체크리스트

- 정적 호스팅(예: Netlify/Vercel/S3+CDN) 사용 시 HTTPS 강제, 기본 보안 헤더
  (X-Content-Type-Options, Referrer-Policy 등)는 호스팅 플랫폼 기본값을
  따르되, 커스텀 서버로 서빙하게 되면 이 문서에 실제 설정을 기록한다.
- `public/`에 올리는 파일(이미지 등)에 EXIF 위치 정보 등 의도치 않은
  메타데이터가 없는지 확인한다.
